Anti-Time Theft Logger Privacy & Data Protection Policy

Effective Date: July 2026

Anti-Time Theft Logger is committed to protecting user privacy in compliance with the Personal Information Protection and Electronic Documents Act (PIPEDA) and British Columbia's Personal Information Protection Act (PIPA).

2. Data Minimization & Collection Limits

We strictly minimize data collection to protect your privacy wrapper. Anti-Time Theft Logger collects:

  • Timestamps: Exact start and end times of user-initiated compliance tracking windows.
  • Network Fingerprint: Public IP addresses to verify isolation from corporate routing environments.
  • ISP/Network Provider Name: We look up the internet service provider or network organization name associated with your public IP address, via the third-party lookup service ipwho.is. This is shown alongside (never in place of) your raw IP address, for readability. Your IP address is sent to ipwho.is to perform this lookup.
  • Minimized Domain Contexts: We extract and log only top-level domain names (e.g., github.com, not mail.google.com — subdomains are stripped along with everything else below). We explicitly strip and do not collect full URLs, private sub-paths, subdomains, or query strings to prevent session-token leakage or exposure of an employer's specific internal systems. This is captured continuously for every tab opened or navigated to during a session, not just what's open when the session starts and ends, so a page you visited and closed mid-session is still reflected in the record.
  • Contemporaneous Note: An optional, user-authored free-text description of the session's activity, entered voluntarily before ending a session.
  • Active Engagement Time: While a session is running, we track whether you are actively using the browser (via the OS-level idle signal) and whether your active tab is on a supported AI assistant site (currently claude.ai, chatgpt.com/chat.openai.com, gemini.google.com, perplexity.ai, copilot.microsoft.com, poe.com, meta.ai, grok.com, chat.deepseek.com, chat.mistral.ai, you.com, character.ai, or huggingface.co/chat). Time is only counted while all three are true at once: you are not idle, that window has OS focus, and that tab is one of the listed sites.

3. Deep Engagement Logging (AI Sites Only)

On the same supported AI assistant sites listed above, and only while a session is actively running, we capture a short fragment of each prompt you submit — never the full text, and never the assistant's response:

  • Prompts: the first 15 words you typed, truncated with "…" if longer.
  • What we do NOT capture: the remainder of any prompt, the assistant's response, file attachments, images, or any content once a session is not running.

These fragments exist for one purpose: so that if you ever review your own log, you can confirm at a glance what you were actually working on — enough to distinguish "drafting the ATTL SOW" from something unrelated, without the log becoming a searchable archive of your full conversations. This capture happens locally via a content script running on the pages listed above; the same backup and deletion rules in Sections 4 and 5 apply to it.

Adding a site yourself: the extension's settings let you add any additional domain (e.g. an AI tool not on the list above) to this same capture behaviour. Doing so triggers Chrome's own permission prompt for that specific site — nothing is added silently — and the site then follows every rule on this page exactly the same way the pre-listed ones do: capture only while a session is running, same word limits, same never-full-text rule. You can remove a site you've added at any time from the same settings screen.

4. Data Subject Rights (Right to Deletion)

Under Canadian law, you retain full ownership of your data context. You may request deletion of your historical records at any time by emailing support@oscarpoon.ca with your Backup ID. Deletion is carried out manually rather than instantly through an automated dashboard — see Section 5 below for why.

5. Data Integrity & Tamper-Proofing

Your session log is protected by three mechanisms designed so that no one — including us — can quietly alter a past entry:

  • Hash chain: every entry is cryptographically linked to the one before it. Editing an old entry breaks the chain in a way that's mathematically detectable.
  • Append-only database: the database itself refuses every edit or delete request from our running application, including our own automated backend. This is why deletion requests (Section 4) are handled as a deliberate, individually logged manual action rather than an instant automated one.
  • Public, independent timestamping: once a day, we publish a fingerprint of the entire log, a short scrambled code, never the log itself, to a public record outside our own systems. Nobody can reconstruct your session data from that code; it's only useful for confirming a given day's log hasn't changed since. This means even a full database wipe couldn't produce a fake history that matches a previously published fingerprint.

Full details: How the Log Is Tamper-Proof.

6. Optional Native Helper (macOS Desktop App Tracking & Git Correlation)

This capability is off by default. It only activates if you separately install a native helper program on your own Mac (via the native-host/install.sh script bundled with this extension) — Chrome extensions cannot see anything outside the browser on their own, and we do not install anything outside the browser automatically.

If you have installed the native helper, and only while a session is running:

  • Frontmost desktop app: once a minute, we ask the helper which application is frontmost on your Mac (e.g. "Claude", "Code", "Terminal") and whether you've touched the mouse/keyboard in the last minute. If you have, that minute is credited to that app's running total for the session. We do not see window titles, on-screen content, keystrokes, or which app was frontmost for the other 59 seconds of that minute.
  • Git commit correlation: only if you've entered a repository path in the extension's settings, at session end we ask the helper to run git log against that one repository, scoped to your session's start/end timestamps, and record each commit's hash, timestamp, and message. We never read any other repository, and never read file contents or diffs — only commit metadata.

Both features run entirely locally between the extension and the helper program on your own machine; neither is sent anywhere except as part of your own session log, under the same collection, deletion, and integrity rules described in Sections 2, 4, and 5 above.
